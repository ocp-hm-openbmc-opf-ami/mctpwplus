commit 92b684ac42f3e578a071894db326eef672f7302e
Author: Ewelina Walkusz <ewelinax.walkusz@intel.com>
Date:   Thu Oct 16 08:25:42 2025 +0200

    Resolve issues with spawn on latest Boost (v1.88) (#124)
    
    Since Boost 1.88 the default completion token, provided in
    boost::asio::spawn's third argument, has changed to
    boost::asio::deferred, which results with coroutines not spawning at
    all. The common way to fix that is to replace default argument with
    boost::asio::detached, but this has a negative effect of not being able
    to catch any exception thrown inside a thread. This change addresses the
    issue by introducing a wrapper for boost::asio::spawn with custom
    completion token, which rethrows any exception that may be thrown inside
    a coroutine.
    
    Tested: Unit Test Validation with Boost v.1.88
    
    ---------
    
    Signed-off-by: Ewelina Walkusz <ewelinax.walkusz@intel.com>

    [mctpwplus] Partial matching for vdpci endpoints
    
    This patch implements a partial matching mechanism to allow vendor
    defined messages without vendor id and/or vendor message type. Both
    fields are required and used for matching before, thus some non-Intel
    devices will not work.
    
    The allowed matching rules are:
    No matching:  All devices support vdpci message.
    VID only:     Devices support vdpci message with specific VID.
    VID and Type: Devices support vdpci message with specific VID, and
                  supports specific message type (existing behavior)
    
    A new MCTPConfiguration constructor is also added for VID-only match.
    MCTPConfiguration(MessageType msgType, BindingType binding,
                      uint16_t vid)
    
    Tested:

    The upper layer applications like PLDM could send and receive MCTP
    packets over d-bus (using methods exposed by mctpd). However,
    this makes the application design tied to d-bus. Since mctpd
    can potentially move towards socket based interfaces/in-kernel
    implementation, a wrapper library is provided which hides the
    underlying IPC mechanism (D-Bus/Socket). This way, applications
    need not be redesigned if mctpd changes its interfaces.
